T1 · Infix → prefix (src/tokenizer.cpp, src/infix_prefix.cpp)

Work on tokens, never characters: reversing characters would turn x12 into 21x. Steps: tokenize; reverse the list; swap ( and ); run infix → postfix with an operator stack; reverse the result.

Tokens: ( ( p + ( ~ q ) ) > r ). Reversed and swapped: ( r > ( ( q ~ ) + p ) ).

Reversing the output gives the prefix expression > + p ~ q r.

Why the pop rule is ≥ for > and strict > for *, +. The string is read backwards, so associativity flips. p>q>r reads r>q>p; on meeting the second > the first one must already be emitted (pop on equal precedence), giving r q > p >, which reverses to > p > q r = p>(q>r). Popping only on strictly greater would give > > p q r, the wrong left-associative parse. For + and *, which are left-associative, equal precedence must not pop. A separate state machine rejects malformed input (p q, p+, unbalanced parentheses) with a clear message before conversion.

Complexity: O(n) time, O(n) space — each token is pushed and popped at most once.

T2 · Prefix → parse tree (src/tree_build.cpp)

Scan the prefix tokens right to left with a stack of subtrees. An atom pushes a leaf. ~ pops one subtree and stores it in right (the NOT node's left stays null, so in-order prints ~ before its operand with no special case). A binary operator pops twice: the first pop was pushed last, i.e. is the left operand. Exactly one subtree must remain.

freeTree is iterative (explicit stack): a recursive delete would overflow the call stack on a left-deep CNF tree. Malformed prefix input frees everything built so far and throws. Complexity: O(n) time, O(n) space.

The recursive versions append to one shared output buffer; returning and concatenating strings at every level would be O(n·h). In-order cannot be the textbook "push left chain" loop: parentheses must be printed before the left subtree and after the right, and a NOT node has no left child. So each frame carries a state: OPEN prints ( and schedules the left subtree, MIDDLE prints the operator and schedules the right subtree, CLOSE prints ). Post-order needs the last-visited pointer to tell "coming back from the right subtree" from "not been there yet"; this keeps the stack at O(h) where the two-stack variant needs O(n).

T4 · Height (src/height.cpp)

Convention: height(null) = -1, height(leaf) = 0. Recursive: 1 + max(left, right). Iterative: level-order BFS with std::queue; the number of levels minus one is the height. For case A the levels have widths 1, 2, 2, 1 → 4 levels → height 3. Time O(n); space O(h) call stack (recursive) or O(w) queue, w = widest level (iterative).

T5 · Evaluation and truth table (src/eval.cpp)

evaluateRec is a post-order recursion; evaluateIter is the same post-order walk with a value stack (the right operand is the top of the stack when an operator is reached). a > b is (!a) || b. Both children are always evaluated, so a missing atom is reported wherever it sits. collectAtoms returns the distinct atoms in natural order (x2 before x10). The truth table has 2k rows; row i gives atom j the bit (i >> (k-1-j)) & 1, so the first atom is the most significant bit and row 0 is all-false. Above 20 atoms the table is refused with an explanation (see Analysis).

DIMACS input (src/cnf_reader.cpp)

readDimacs skips c lines, stops at %, accepts clauses spanning lines or sharing a line, and warns (without failing) when the clause count differs from the header. cnfToInfix writes literal k as xk and -k as (~xk), each clause as a left-deep disjunction, and the clauses as a conjunction that is either LEFT_DEEP (height Θ(clauses), the stress case) or BALANCED (midpoint split, height ≈ log₂(clauses) + clause depth).
